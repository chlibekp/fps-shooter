# Phase 5 report — Maps and assets

Goal (roadmap): three production maps and the art pipeline for them —
modular building pieces, props and gadget models built in Blender — on top
of the gameplay systems of Phases 1–4.

**Result:** three production maps are playable on the server and in the
client netcode. Each is validated automatically: spawns, objective sites,
and walkability from both sides. The Blender pipeline now produces 10
assets: props, map kit pieces and gadget models. The Unreal side has code to
import them and place them over matching map geometry. As in every phase so
far, that Unreal code is only mock-compiled: it has not been run in the
engine, because none is available here.

## Maps (`Tools/MapTools`, `Shared/Definitions/maps`)

| Map | Layout | Solids | Destruction cells | Objective sites |
|-----|--------|-------:|------------------:|-----------------|
| Harbor Warehouse (`harbor`) | 36 × 24 m hall (brick to 3.5 m, metal above), two-storey office block, mezzanine, barricaded loading dock, container yard | 275 | 7,549 | Upper Office, Storage |
| Hillside Villa (`villa`) | Two-storey house, breakable wooden upper floor, basement with wine cellar, walled garden, shed, terrace, cars | 234 | 10,467 | Master Bedroom, Basement |
| Consulate (`consulate`) | Office building around a double-height atrium (glass balustrades), courtyard with gatehouse and fountain, service alley | 392 | 13,748 | Archives, Ambassador Office |

Each map has 5 attacker spawns outside and 5 defender spawns inside. Maps
are generated by scripts using `mapkit.py`:
* walls are split into panels of at most 2.4 m, the unit of reinforcement;
* doors and windows are cut out of walls, with breakable doors, glass and
  plank barricades;
* floors have holes and breakable hatches;
* stairs use steps of at most 0.25 m;
* maps carry named objective sites.

Interior doorways are open so defenders can move around; exterior doors
are closed and breakable.

The server takes a map by name (`--map harbor`) or path. Clients use
`-map=harbor`.

## Map validation (`Shared/Simulation/rust/tests/maps.rs`)

For every map file:
* it loads, and its name matches the file;
* every spawn is free and on the ground;
* there are at least 5 spawns per team and 2 objective sites;
* **each defender spawn** can walk to every site with the map intact;
* the attackers can reach every site when breachable surfaces are opened.

Walkability is a search over a 0.25 m grid of feet positions using the real
player box: 0.35 m steps, 0.45 m jumps, drops up to 4 m, and crouch
passages. While the maps were being built it caught:
* spawns placed inside furniture;
* a map-kit bug that put lintels across whole upper-floor doorways
  (openings were measured from z = 0 instead of the wall's base);
* closed interior doors that cut defenders off from their own sites.

Other checks:
* **CI regeneration:** CI regenerates all maps from their scripts and fails
  if the committed JSON differs.
* **Golden vectors:** they carry every map's geometry hash, so the C++
  parser is checked against Rust on all four maps.
* **5v5 lobbies:** an end-to-end test runs one on each production map. All
  clients see each other, prediction holds (≤ 2 corrections per client) and
  the teams are 5 v 5. It runs in its own test binary so its load does not
  disturb timing-sensitive tests.

New in the pipeline:
* **Paint system:** `tc.paint` / `tc.painted_material` give one texture set
  for multi-surface hardware, with metallic baked per texel.
* **Fix — black metals:** base colour is now baked with metallic forced to
  0. Before this, every metal baked black.
* **Fix — wrong pivots (and a build guard):** `join` keeps the first
  part's object transform, and the pivot helper dropped it. 7 of 10
  assets, including the Phase 1 crate, were exported up to 1 m away from
  their pivot. In Unreal they would have imported up to a metre off their
  map positions. The transform is now baked into the mesh first. Every
  build now fails unless the exported mesh's pivot is at the bottom centre
  (within 2 mm).
* **Unreal import:** `unreal_import.py` imports all exports into
  `/Game/Environment/Props` with LOD1, collision, texture settings and
  material instances. It is untested; no editor is available here.

Game-side use (mock-checked):
* **Arena builder:** dresses map solids whose tag and size match a prop:
  crates, jersey barriers, doors, and window frames around glass. A
  destructible prop shows until its first cell breaks, then gives way to
  the surviving cells.
* **Gadget visuals:** `ATfpsGadgetFx` draws the gadget models. Both fall
  back to the placeholder shapes until the assets are imported.

## Known issues and limitations

* The Unreal client, the import script and the dressing code have not
  been run in Unreal Engine.
* Walls and floors are still drawn as tinted cell cubes. The brick panel
  material needs world-aligned UVs on the cell instances before it can
  replace them.
* Placed gadgets are drawn without the surface orientation.
* Objective sites are not yet part of the geometry hash. Game modes that
  use them arrive in Phase 6, and the hash will include them then.
* No audio assets yet.
