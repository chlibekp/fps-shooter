# TacticalFPS (working title)

A realistic, tactical multiplayer first-person shooter: a **Godot 4** client
and an authoritative **Rust** dedicated server. All art and sound is original
and generated by code or by scripts in Blender.

**Status: Godot client (see [GODOT.md](Documentation/GODOT.md)).**

**What works:**
- **Movement:** run, sprint, crouch, prone, lean, vault and aim down sights,
  with client-side prediction; doors open and close; light, medium and
  heavy armour.
- **Combat:** data-driven weapons. The server resolves shots with
  lag-compensated hitscan, bullet penetration and damage.
- **Destruction:** walls, windows, doors, barricades and floors break into
  cells that every client's collision agrees on.
- **Gadgets:** attackers carry frag grenades, flashbangs, breaching charges
  and recon drones. Defenders deploy barricades, reinforce walls and place
  cameras, motion sensors and jammers.
- **Maps:** three production maps (Harbor Warehouse, Hillside Villa,
  Consulate).
- **Modes:** team deathmatch, elimination (including 1v1) and defuse rounds.
  A lobby service with invite codes runs custom matches.

**The client:**
- **Built for free:** on standard GitHub runners for Windows, Linux and macOS,
  with no account or login. Each release carries a download you unpack and
  play.
- **Rendering:** Godot's Forward+ renderer with procedural surfaces, global
  illumination, volumetric fog and smoke, GPU particles, procedural
  characters and weapons, and 3D audio from the synthesiser.

**Verified:** the exported Linux game is checked in CI and here by joining a
practice match. The Windows and macOS builds are produced by CI but have not
been played on those systems yet.

Earlier milestone reports (1–7) describe an Unreal Engine 5 client that was
only ever mock-compiled. It was replaced by the Godot client, so that the game
can be built without an engine licence or login (see
[ARCHITECTURE.md](Documentation/ARCHITECTURE.md), decision 16).

## Repository layout

```
Game/                   Godot 4 project (the game client)
  scripts/ shaders/     world, player, operators, effects, audio, HUD, menus
  native/               native extension: the client core behind a JSON API
  tests/                headless tests (native extension against a server)
Client/
  Core/                 engine-independent C++ client core: netcode, prediction,
                        map / weapons / gadgets, procedural sound synthesis
  NetCoreTests/         CMake: core unit / conformance / live tests, CLI client
Server/                 Rust authoritative dedicated server (src, tests, benches)
Lobby/                  Rust lobby service (invite codes, custom matches)
Shared/
  Protocol/             protocol spec + Rust protocol crate
  Simulation/           Rust shared movement simulation crate
  Definitions/          maps (JSON), weapons, gadgets, conformance vectors
Tools/
  DevClient/            Rust headless reference client + bots
  AssetPipeline/        Blender asset scripts
  MapTools/             map generators / validation
Assets/                 Blender sources, exports (FBX + PBR textures)
Scripts/                build / run / test / package scripts (bash + PowerShell)
  godot/                fetch Godot, build the extension, export the game
Documentation/
```

## Requirements

* Rust 1.80+ (`rustup`), CMake 3.16+ and a C++17 compiler
* Godot 4.7.2 for the client: `Scripts/godot/fetch_godot.sh` downloads the
  official release (no account needed)
* Blender 4.x to rebuild assets (optional; outputs are committed)

## Play

Download `TacticalFPS-<version>-<os>` from the GitHub release, unpack it and
start:
- `Practice` for a match against bots on your computer;
- `Play` for the main menu, where you can host a lobby, join with an invite
  code, or connect directly.

See [RELEASES.md](Documentation/RELEASES.md).

## Develop

Fetch Godot and build the native extension:

```bash
Scripts/godot/fetch_godot.sh
```

```bash
Scripts/godot/build_extension.sh
```

Run the server, then the game from the project:

```bash
Scripts/run_server.sh --bind 0.0.0.0:7777 --map harbor
```

```bash
Scripts/godot/godot.sh --path Game -- --connect 127.0.0.1:7777 --map harbor --name Me
```

Without `--connect`, the game opens the main menu. Its Practice entry starts
a local server and bots by itself; from the project it uses the server built
in `target/release`.

Run every automated test (Rust, C++ core, live C++ ↔ Rust, and the Godot
native extension against a live server when Godot has been fetched):

```bash
Scripts/test_all.sh
```

Export the game and package the player download for this platform:

```bash
Scripts/godot/fetch_godot.sh --templates
```

```bash
Scripts/godot/export_game.sh Linux
```

```bash
Scripts/package_game.sh v0.0.0-local Linux build/export/Linux
```

Headless clients and load-test bots:

```bash
Scripts/run_clients.sh --headless 2 127.0.0.1:7777
```

```bash
target/release/tfps-bot --server 127.0.0.1:7777 --count 16 --pattern random --seconds 30
```

On Windows use the matching `Scripts\*.ps1` scripts, or run the bash scripts
from Git Bash.

## In-game controls

WASD move · Mouse look · Shift sprint · Alt slow walk · C toggle crouch (Ctrl
hold) · Z toggle prone · Space jump (vault over low cover and through windows while moving) · Q/E lean · Right mouse aim (ADS) · Left
mouse fire · R reload · F use (plant, defuse, reinforce) · 1/2 weapons ·
3–6 gadgets · F3 net stats · Esc menu.

Everything is rebindable in Settings → Controls. Settings are saved in the
game's user folder.
