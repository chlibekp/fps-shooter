# Map gameplay definitions

Each `<map>.json` describes the **gameplay geometry** of a map. It is loaded by
the Rust server (collision, spawns) and by the Unreal client (prediction
collision and the graybox/blockout). Visual art is layered on top in Unreal.

Coordinates: meters, Z-up, X forward, Y right (see ARCHITECTURE.md, decision 7).

```json
{
  "name": "test_arena",
  "kill_z": -30.0,
  "solids": [
    { "min": [x, y, z], "max": [x, y, z], "material": "concrete", "tag": "floor" }
  ],
  "spawns": [ { "pos": [x, y, z], "yaw": 0.0, "team": 0 } ]
}
```

* `material`: `concrete`, `brick`, `wood`, `drywall`, `metal`, `glass`,
  `reinforced`, `dirt`.
* `tag`: free text used by the client for visuals (`floor`, `wall_*`,
  `crate`, `stairs`, ...).
* Spawn `pos` is the feet position.

The server sends a 64-bit FNV-1a hash of the solids (min/max float bits +
material) and `kill_z` in `ConnectAccepted`. The client computes the same hash
from its copy and refuses to play on a mismatch.

`test_arena.json` is generated by `Tools/MapTools/build_test_arena.py` — edit
the script, not the JSON.
